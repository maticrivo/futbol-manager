# Bag Duty Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Assign a fair, random weekly "who takes the equipment bag" member and backup from the match roster, notify the group, and record who actually took it.

**Architecture:** A new `bag_duties` table holds one row per match (assigned, backup, actual). A `src/domain/bag.ts` module computes credits from past rows and draws at `kickoff − 1h`; the tick and page-load path both call it idempotently. Members see the duty on the home card; admins record the real taker on the admin match page.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Drizzle ORM + PostgreSQL 17, next-intl, web-push, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-27-bag-duty-design.md`

## Global Constraints

- No new npm dependencies.
- PostgreSQL snake_case columns via Drizzle; TypeScript camelCase fields; integer identity primary keys.
- All scheduling logic uses `Asia/Jerusalem`; timestamps are `timestamptz`.
- Copy must be added to all three locales: `messages/en.json`, `messages/es.json`, `messages/he.json`.
- Admin mutations are audit-logged with `writeAudit`.
- Every draw and notification must be idempotent under repeated ticks and concurrent page loads.
- Tests run against `TEST_DATABASE_URL`; migrations are applied by `tests/global-setup.ts`, so generated migrations must be committed.
- Before the final task passes: `npm test`, `npm run lint`, `npm run build`.

## Review Focus

- Assignee withdraws or is removed after the draw: no redraw; the card still names them; if the backup actually took it, the admin record credits the backup, not the assignee.
- Admin never records the taker: the assigned member is credited, even if they were actually absent (explicit rule).
- Match cancelled after the draw: its duty must not count toward fairness.
- Everyone has already taken it once: the next draw goes to whoever took it longest ago, never a fresh random repeat.
- Guest entries exist on the match: guests must never be assigned or backed up.
- A page load draws before the next tick: the tick must still send the push exactly once, and never redraw.
