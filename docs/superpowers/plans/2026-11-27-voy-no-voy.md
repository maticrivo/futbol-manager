# Voy / No voy — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let members answer **No voy** for the upcoming match or return to undecided, send the signup-open and lock-reminder pushes only to members who have not answered, and show a "Not going" list to everyone and a "No answer yet" list to admins.

**Architecture:** A new `declined` value on `entry_status` stores No voy; `withdrawn` keeps meaning "left without saying no" and is the stored form of undecided. A new `src/domain/responses.ts` owns the status → response mapping, the visibility policy and the response lists. `decline` and `clearDecline` live in `src/domain/entries.ts` next to `signup` and `withdraw`. `processDueNotifications` filters two categories by response. The home page and admin match page render a role-agnostic `ResponsesPanel`.

**Tech Stack:** Next.js 16, React 19, TypeScript, Drizzle ORM (Postgres 17), next-intl, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-27-voy-no-voy-design.md`

## Global Constraints

- Answers are accepted only in phases `open` and `guest` (`phaseAt` in `src/domain/matchView.ts`). `before` is deferred (see the spec).
- Status → response mapping exists once, in `responseOf`. New code must not repeat status lists; existing allowlists are left alone.
- The unanswered list is filtered inside `listMatchResponses`; pages never decide visibility themselves.
- Freeing a confirmed spot or an offer always runs `offerNext` in the same transaction, as `withdraw` does.
- Every mutation keeps the existing lock order: match row first (`lockMatch` / `lockMatchForEntry`), then entry rows.
- The migration is forward-only and contains only the enum addition.
- Every new string exists in `en`, `es` and `he`. New components use logical spacing (`ms-`/`me-`, `ps-`/`pe-`).
- Do not change the guest-phase, bill-ready or payment-reminder audiences, the WhatsApp copy, or the existing `Sign up` / `Join the waiting list` / `Leave the waiting list` labels.

## Review Focus

- **Spot release on decline:** declining from `confirmed` or `offered` must offer the spot to the queue head in the same transaction; declining from `queued` frees nothing.
- **Privacy of the unanswered list:** a non-admin's rendered home page must not contain unanswered members' names.
- **Notification log claims:** skipped members must not be written to `notification_logs`, so returning to undecided inside the window still gets the reminder.
- **Roster order:** re-joining via `signup` or `adminAddEntry` moves the member to the end; queue order is unchanged.
- **Offer push key:** a second offer on a reused entry row must be pushed.
